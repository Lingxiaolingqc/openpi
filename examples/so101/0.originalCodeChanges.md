# OpenPI 原始代码改动记录（SO-101 / LeIsaac）

本文档集中记录本仓库为了完成 SO-101、LeIsaac、OpenPI π0.5 数据采集与训练链路而加入的改动，便于学习、复现、代码审查和日后回退。

## 记录边界

- 对比基线：`b730105`（`Change the video size of the libero output`）。
- 当前开发分支：`libero-repro`。
- 记录范围：从 `675a7a6` 开始加入的 SO-101/OpenPI 改动，以及本次训练退出清理修复。
- 基线之前的 LIBERO 改动不归入本文档，也不声称由本轮工作创建。
- Git 提交中的 author 是仓库配置的提交身份，不等同于本文档对代码来源的归属判断。

## 改动后的完整链路

```text
Windows SO-101 Leader (COM7)
  -> 本机串口读取、标定文件与安全 PID/力矩设置
  -> ZeroMQ 发布 tcp://127.0.0.1:5556
  -> SSH reverse tunnel
  -> 服务器 LeIsaac LiftCube 仿真与网页控制
  -> LeIsaac 原生 HDF5 成功轨迹
  -> 独立 OpenPI uv 环境转换为 LeRobot 0.4.2
  -> 计算 normalization statistics
  -> OpenPI pi0.5 SO-101 LoRA/full 训练
  -> WebSocket 策略服务返回 6 维 SO-101 动作
```

Isaac Sim 环境与 OpenPI/LeRobot 环境保持隔离。原因是 LeRobot 0.4.2 与已验证的 Isaac Sim 5.1 Python 依赖存在版本冲突，尤其是 `packaging`。因此仿真环境只负责录制原生 HDF5，转换与训练在 OpenPI 的 `uv` 环境中完成。

### 8. 训练结束时显式释放全部训练资源

文件：

- `scripts/train.py`
- `scripts/train_test.py`
- `src/openpi/training/data_loader.py`
- `src/openpi/training/data_loader_test.py`
- `src/openpi/training/config.py`
- `src/openpi/training/config_test.py`

问题背景：

- 两张 RTX 3090 的 FSDP 一步训练和 step 0 checkpoint 保存已经成功。
- Orbax 日志显示异步保存线程与 finalize 都完成，但 Python 进程退出阶段出现过整机重启。
- 原代码最后只调用 `checkpoint_manager.wait_until_finished()`。该方法只等待未完成的 save，并不关闭 manager 的线程池和内部对象。
- 第一次修复验证后，日志已经打印 `Checkpoint manager closed`，但主机仍在随后的解释器退出阶段异常复位。
- 默认 DataLoader 使用两个 `persistent_workers`；原训练函数不关闭 iterator 或 loader。CPU 训练的 native crash 栈中也出现了两个 multiprocessing queue feeder 线程。

本次修复：

- 在 checkpoint manager 创建后立刻进入 `try/finally`。
- 正常训练结束或训练初始化/执行抛异常时，均调用 `checkpoint_manager.close()`。
- `close()` 自身会等待异步保存结束并关闭内部资源，因此不再使用仅等待的末尾调用。
- 增加 `Closing checkpoint manager` 与 `Checkpoint manager closed` 两条日志，便于精确区分重启发生在 Orbax 关闭之前还是之后。
- 新增回归测试：模拟训练初始化失败，验证 manager 仍然只关闭一次。
- 为通用 DataLoader 增加幂等 `close()`，显式停止 PyTorch persistent workers；RLDS loader 也会在底层 dataset 支持时转发 `close()`。
- 训练退出时按顺序关闭 checkpoint manager、进度条、data iterator、data loader 和 W&B run，并为每一阶段打印开始/完成日志。
- SO-101 full 与 LoRA 配置默认设为 `num_workers=0`。这会牺牲部分数据加载吞吐，但避免在尚未稳定的服务器退出路径中保留 worker 子进程。
- 新增 DataLoader 幂等关闭测试、训练加载失败时的资源关闭顺序测试，以及 SO-101 worker 配置断言。

这些修复消除了已确认的 Orbax 和 DataLoader 清理遗漏，但不能单独证明整机重启一定消失。如果服务器在打印 `Training resources closed` 后仍重启，应继续检查 JAX/XLA、NCCL、NVIDIA 驱动或硬件在多 GPU context teardown 阶段的问题。

- 专家 smoke 可把前置相机按固定步距增量保存为 JPEG 序列，同时写入包含 phase、关节、gripper、jaw、方块及盒内偏移的 `trace.jsonl`、最终 `result.json` 和离线 `index.html` 播放器；失败案例目录可以直接从服务器 `scp` 到 Windows，不依赖 Isaac 环境或视频编解码器回放。
- 新增独立 `legacy_gripper_anchor` 专家，完整保留 legacy 的抓取、抬升和搬运，只在放置阶段按实时三维 `jaw - gripper` 偏移把盒中心 jaw 目标反算成 gripper IK 目标；jaw 未连续稳定对齐时会在开夹爪前超时终止，原 `legacy` 不受影响，可继续作为历史基线。
- 新增独立 `legacy_gripper_anchor_align_then_lower` 顺序消融专家：保留 legacy 完整 pose IK 与固定世界姿态，先在进入阶段时的实测高位完成 jaw X/Y 连续对齐，再锁定盒中心 X/Y 垂直下降；下降后的 X/Y/Z 需再次连续稳定十步才允许释放，两个阶段分别报告超时。其目标显式写成 `desired_jaw_w + (gripper_pos_w - jaw_pos_w)`，即期望 jaw 位置加实时 jaw-to-gripper 偏移；它与原反馈写法代数等价，改写用于明确坐标含义而非制造伪对照。
- 新增独立 `legacy_gripper_anchor_position_align_then_lower` 约束消融专家：阶段、目标和计时均复用先对齐后下降版本，仅在高位 `align_over_box` 移除全部姿态行，以 position-only IK 求解 XYZ；Z 是进入阶段时捕获的实测高度。进入下降阶段立即恢复 legacy 完整 pose IK，从而单独检验高位 align 的姿态过约束。
- 新增独立 `legacy_gripper_anchor_weighted_position_align_then_lower` 冗余解消融专家：高位 align 仍只求解 XYZ，但使用按关节名配置的加权 DLS；`shoulder_pan/shoulder_lift/elbow_flex/wrist_flex/wrist_roll` 运动代价依次为 `0.25/1.0/1.0/1.5/2.0`，阻尼为 `0.05`，因此在能降低位置误差的冗余解中优先底座而非硬编码底座角度。下降恢复 legacy 完整 pose IK。
- 新增独立 `legacy_gripper_anchor_safe_planar_align_then_lower` 专家，保留 position-only 与 weighted-position 失败实验作为对照：抓取、搬运、先高位对齐后下降的顺序与 legacy 一致；高位对齐只求解 jaw X/Y 加三维姿态，Z 从 IK 误差与 Jacobian 中移除。Z 只按真实物理风险门控：方块底部高于盒壁至少 `0.015 m`、机器人包围体净空至少 `0.010 m`、盒接触力不超过 `0.25 N`，不再使用实验证明过严的入口高度 `±0.020 m` 人工区间。越界会在下一动作前终止并记录原因，不使用 position-only 动作补救；下降恢复 legacy 完整 pose IK。
- 新增配对对照 `legacy_gripper_anchor_safe_xyz_tilt_align_then_lower` 与 `xyz_tilt(xyz+orientation_xy)` IK 模式：高位对齐控制 XYZ 和世界坐标系姿态误差 X/Y 两行，释放世界 yaw，因此仍是五行任务对应五个手臂关节。Z 保持进入 align 时的实测高度，避免 position-only 的三维姿态自由漂移和 full-pose 六行任务的过约束；物理净空与接触门控和不控制 Z 的版本完全相同。
- 新增独立 `legacy_gripper_anchor_safe_xyz_pitch_pan_align_then_lower` 与 `xyz_pitch_joint(xyz+orientation_y+shoulder_pan)` 模式，验证“底座开始转动后停止”是否来自任务中缺少持续关节目标。专家在 align 入口根据机器人根节点、实时 jaw 与盒中心的世界 XY 方位差计算 `shoulder_pan` 目标；按已审计的 SO-101 方向约定从入口关节角减去该误差，最大修正 `0.35 rad` 并限制在 soft joint limits 内。高位 align 的五行任务为 XYZ、基座坐标系 pitch 和显式 shoulder-pan 误差。smoke 每 25 步输出目标/实际底座角、IK 关节增量、任务误差与 Jacobian 奇异值，以区分求解器停止请求、执行器跟踪不足和近奇异状态。
- 新增独立 `legacy_gripper_anchor_relaxed_ik` 消融变体：下降结束前仍用 legacy 完整 pose IK，对齐前 120 步使用 `0.1` 姿态权重，仍未收敛则退化为 position-only IK；达到连续稳定条件后才释放，搬运期间检测到抓取丢失则在下一物理步前终止。smoke 会在运行模式切换时打印 `expert_ik_runtime_mode`，并周期输出 jaw 目标、误差和稳定计数。
- 新增独立 `legacy_gripper_anchor_planar_ik` 变体与 `planar_pose(xy+orientation)` IK 模式：最终对齐从 Jacobian 中真正移除 Z 平移行，用 jaw X/Y 加三维姿态组成五行任务；方块底部净空改为 `>=0.010 m` 的安全不等式，`>=0.015 m` 才恢复横移，每步 XY/抬升均限制为 `0.002 m`。lower-arm、wrist、gripper、jaw 使用保守包围球高度门控并各自配置过滤到五个盒部件的 ContactSensor；这些传感器只为该专家启用，不改变 legacy 对照环境。实测接触、抓取丢失或无法捕获释放姿态都会在开夹爪前终止。录制 trace/result 同步写入 IK 与安全字段。
- 不连接真实 Leader，不写动作，不录制数据，也不修改下载的 LeIsaac 资产。
- 根据实测坐标把目标盒中心放在 `(0.520, -0.36161)`，即沿方块的 `+X` 方向横向分离，同时维持接近的 `Y` 前伸距离。
- 用五个绿色运动学刚体组成底板和四面墙，不依赖新的外部 USD 资产。
- 五个部件分别使用环境下的独立顶层 prim；这是为了兼容当前 IsaacLab shape spawner，避免嵌套 regex 路径要求尚未创建的 `TargetBox` 父 prim。
- 成功判据同时检查方块位于盒内、低于墙顶并且线速度不超过 `0.15 m/s`，避免方块从盒子上方掠过时误判。
- 有界 smoke 先验证正常 reset 不成功，再把方块临时传送到盒内验证判据为真；传送只用于测试，不属于脚本专家或数据生成轨迹。
- 初版脚本专家使用 LeIsaac 的 `so101_state_machine` 绝对位姿 IK action，按接近、下降、闭合、抬升、横移、入盒、释放、撤离和稳定等待九个阶段运行。
- 该状态机 action 的 8 维不是 6 个关节角，而是末端局部坐标位置 3 维、单位四元数 4 维和二值夹爪命令 1 维；DLS 逆运动学把前 7 维转换为 5 个手臂关节目标，最后 1 维控制第 6 个夹爪关节。
- 专家 smoke 暂时关闭环境自动成功终止与超时，防止检查最终方块位置前自动 reset；它输出阶段切换、最终盒内偏移、速度和成功状态。
- 抓取失败诊断会在每次阶段切换时输出 gripper/jaw/cube 世界坐标、jaw 到 cube 距离、夹爪关节位置、`pick_cube` 判据和该阶段首个 action，以区分 IK 未到位、几何偏移和夹爪未闭合。
- 首次动态诊断在抬升前达到 `0.01826 m` jaw-cube 距离，满足 `0.02 m` 距离阈值，但夹爪停在 `0.45639 rad`，高于 `0.26 rad` 抓取阈值。因此 RedCubeToBox 状态机把通用闭合目标从 `0.4` 改为 `0.05 rad`，不修改已经到位的 IK 抓取位姿。
- 第二次诊断证明夹爪已闭合到 `0.14367 rad`，但闭合后的 jaw frame 移到距离方块 `0.02757 m` 的位置。脚本据此把抓取目标在世界水平面各修正 `10 mm` 并降低 `20 mm`，使闭合后的 jaw 而不是打开时的 jaw 对准方块。
- `red_cube_to_box_drop_smoke.py` 把方块置于盒子正上方后完全依靠重力和碰撞落入盒内，独立检查下落距离、最终速度、盒内判定和意外 reset，避免把盒子碰撞问题与机械臂抓取问题混在一起。

- 新增 `red_cube_to_box_task/phase_aware_ik_action.py`，只为 `servo` 配置替换 action term，不修改 legacy/adaptive。它保留外部 7 维 pose 命令和总计 8 维 action 契约；抓取与 lift 阶段继续使用完整 pose DLS，进入 transfer 后只把平移误差与 Jacobian 前三行送入同一个 DLS 求解，release/retract/settle 也保持 position-only，避免再次突然施加不可达姿态。单次 runner 在每次阶段切换输出 `expert_ik_runtime_mode`，批量与单次 runner 都输出实际 action-term 类名。
- 服务器在 `445a92a` 的首次静态验收中发现 5 个 Ruff 问题和 1 个格式差异。后续修正没有改变控制算法：`set_position_only` 改为仅接受关键字参数；action-term 查询集中到一个兼容函数，优先使用公开 `ActionManager.get_term()`，只在旧版 IsaacLab 缺少该 API 时读取 `_terms`；必须复用旧版控制器内部目标与 DLS 求解函数的位置均用局部 `noqa` 和注释明确标记，避免把私有 API 访问散落到 runner。单次 runner 同时按 Ruff 的规范重新格式化。
- 第八次服务器验证确认 phase-aware action term 和阶段切换均已生效：抓取到 lift 使用 `pose`，transfer 使用 `position_only`，且 transfer 全程 `pick_cube=True`、jaw-cube 距离约 `0.0034 m`。但是方块误差从 `0.121838 m` 短暂下降到 `0.090567 m` 后持续发散到 `0.378024 m`；gripper 四元数同时从约 `(0.973, 0.201, -0.105, -0.041)` 漂移到 `(0.334, 0.478, -0.576, -0.573)`。这证明完全删除姿态任务会给 5 关节机械臂留下剧烈的自由姿态运动；由于 jaw/cube 相对 gripper 原点存在杠杆臂，姿态漂移会把已抓住的方块甩离平移目标，继续调低 `kp` 不能消除根因。

- `legacy_weighted_servo` 的 seed 42 对照证明 legacy 抓取在相同前 440 步保持成功，但 weighted transport 的误差由 `0.115 m` 先降至 `0.050 m`，随后反向增至 `0.275 m`；方块始终保持抓取，而 gripper 四元数从接近单位姿态漂移到约 `(0.54, 0.30, -0.78, -0.09)`。因此新增独立 `legacy_position_servo`：只把运输姿态权重由 `0.1` 改为 `0.0`，其余 pickup、P 外环、步长、阈值、超时和最终判据均与 `legacy_weighted_servo` 相同，用于判断发散是否由欠驱动 6D IK 的姿态行导致。
- `legacy_position_servo` 同 seed 仍发散，且更早出现目标越过：外环在方块越过目标后正确反向，但实际方块受运动速度影响继续远离，最终 transfer 误差约 `0.45 m`、速度 `0.60 m/s`，同时始终保持抓取。这排除了姿态权重是唯一根因，并表明无速度反馈的离散 P 外环无法对当前隐式关节执行器制动。新增独立 `legacy_pd_position_servo`，保持 position-only IK 和所有位置参数不变，仅加入世界坐标制动项 `-kd * cube_velocity`（初值 `kd=0.02`）及 `0.02 m/s` 到达速度阈值；原 P、weighted 和 legacy 变体不变。
- `legacy_pd_position_servo` 的 endpoint-step 测试仍与 P 版本近似重合：transfer 入口已有约 `0.404 m/s` 方块速度，而最终 hover 目标立即产生 `0.115 m` 位置误差；P/PD 合成量长期超过 `3 mm` 上限，归一化后速度项只能轻微旋转控制方向，无法消除饱和和参考跳变。新增 `legacy_trajectory_pd_servo`，保持相同 pickup、position-only IK、`kp/kd`、步长和阈值，只把 transfer/lower 的最终点阶跃改为从阶段入口方块位置到目标的逐步线性参考；每个 300 步阶段用前 240 步移动参考、后 60 步保持终点，给速度衰减和连续 10 步到达判据留出窗口。
